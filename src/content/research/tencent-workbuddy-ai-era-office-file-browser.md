## 一句话总结

腾讯 WorkBuddy 发布第三波"AI 时代 Office"——独立文件浏览器。右键本地文件 → WorkBuddy 打开 → 左侧看文件、右侧叫 AI，改完直接保存回原文件。"办公三件套"入口从对话框走向你电脑里的每个文件。三波进化：7 月底人机双写（AI 进文档跟你一起改）/ 8 月中 HTML 人机双写 / 这次独立文件浏览器（右键入口）。文件支持 Office 三件套 / PDF / Markdown / HTML / TXT / 图片 / 音频 + 腾讯文档在线文档，可设默认双击。设计：AI 面板默认收起 / 每个标签独立对话上下文 / 不扫磁盘只读主动打开的。三大场景：培训方案 docx 五处修改只写回受影响的段落并附修改清单 / AI 吐的 md 与 html 直接渲染可点改保存 / Excel 问卷转 HTML 单页报告可分享链接。保护：Word 占着文件时 WB 只能看不能改 / 文件别处被改保存前提示刷新或另存。移动端微信里甩过来的 md/html 通过小程序"用其他应用打开"——能查看 + 加入对话变附件卡，不能编辑。整套链路：编辑器来自腾讯文档 → 改完传资料库/腾讯文档/ima/乐享 → 微信接住。6 月易观统计 17 款国内桌面端 AI 原生办公智能体月访问量破 6000 万次，其中 WorkBuddy 2097 万次。微软也把 AI 操作加进了 Windows 文件资源管理器右键菜单。"AI 时代 Office"之争 = 双击这一下的归属权。

## 一、第三波：独立文件浏览器

WorkBuddy 自 7 月以来的三波进化：

| 时间 | 波次 | 关键能力 |
|---|---|---|
| 7 月底 | 第一波 | 人机双写（AI 进文档跟你一起改）|
| 8 月中 | 第二波 | HTML 人机双写 |
| 10 月初 | **第三波** | **独立文件浏览器（右键入口）** |

入口从对话框走向每个本地文件。

---

## 二、独立文件浏览器：产品形态

### 支持文件类型

| 类别 | 类型 |
|---|---|
| Office 三件套 | docx / xlsx / pptx |
| 文本 | PDF / Markdown / HTML / TXT |
| 多媒体 | 图片 / 音频 |
| 在线 | 腾讯文档在线文档 |

设成默认打开方式后 → 双击文件直接进入。

### 三个关键设计选择

| 决策 | 详情 |
|---|---|
| AI 面板默认收起 | 打开文件时右侧对话栏是收着的，先让你安静看文档，要用再点"和 WorkBuddy 对话"|
| 对话跟着文件走 | 一个窗口能开多个标签，切到哪个文件，右边就是哪个文件的对话；也同步到主窗口 |
| 不扫磁盘 | 只读取你主动打开的文件，不会遍历扫描整个硬盘 |

## 三、三大使用场景

### 场景 1：修改 docx（只写回受影响段落）

工作流：
1. 右键《培训方案-V1.docx》→ WorkBuddy 打开
2. 选中写死的某行 → 点"AI 编辑" → 改为"待客户确认"
3. 客户 5 条补充以附件形式发给右侧对话
4. prompt：按附件 5 条修改方案，只改受影响的段落，总时长保持 780 分钟，改完列修改清单 + 自查每天时间加总
5. Cmd + S 保存 → 仍是同一个文件，只有修改时间变了

### 场景 2：AI 吐的 md 与 html 直接渲染可改

| 文件 | 普通打开方式 | WorkBuddy 打开方式 |
|---|---|---|
| .md | 满屏井号星号 | 渲染成排版后正文，可点改 |
| .html | 浏览器只能看不能改 | 点"编辑"切换手动 / AI 双写 |

测试用例：公众号稿 .md + 排版 Skill 输出 .html + 蓝皮书 28 章全是 .md — 全部点哪改哪。AI prompt："按右键打开、选中修改、存回原文件的新流程重写这一节，其他内容不动" — 改动只动这一节，git diff 干净。

### 场景 3：Excel 问卷 → HTML 单页报告

工作流：
1. 右键 18 人训前问卷汇总表 → WorkBuddy 打开
2. prompt：按这份问卷做网页版训前调研报告，给客户 HR 看（各部门 AI 基础、最耗时任务、最该优先讲的 3 个场景 + 依据哪几份问卷）；单页 HTML，手机也能看；数字必须能回到表里
3. 生成的 HTML 默认放在问卷表同一个文件夹，对话里点一下新标签打开
4. HTML 本身支持人机双写：点"编辑"手动改标题 / 选中让 AI 换配色 / 点"退出编辑"自动保存
5. 两条路径：
   - 分享：传资料库 → 生成在线链接 → 设"获得链接的人可查看" → 发客户 HR
   - 上传：选资料库 / 腾讯文档 / ima 知识库 / 乐享 → 团队协作或留作下个项目参考

## 四、保护机制

| 风险 | 保护 |
|---|---|
| 文件正被 Word 占着 | WB 这边只能看不能改 |
| 文件在别处被改过 | 保存前提示刷新或另存为，不把同事修改悄悄盖掉 |

提醒：保存是直接覆盖原文件。模板 / 合同原件这类，先另存一份再改。

## 五、移动端：微信里"用其他应用打开"

3 月 WorkBuddy 小程序上线时已与微信生态打通。这次补上 md / html 短板。

微信本身的痛点：甩进群里的 md / html 文件，点开只有"暂不支持打开此类文件"。

WorkBuddy 解法：提示语下方加选项"在打开方式列表里选 WorkBuddy 小程序"。

| 操作 | 详情 |
|---|---|
| 选"查看" | md 渲染成排版好的文档 / html 渲染成网页 / svg 也能看 |
| 选"加入对话" | 文件变成附件卡片放进输入框，补一句要求让 AI 干活 |

实际效果：作者把 Instinct + Jev 模型调研报告 .md 直接发到群里 → 用小程序"加入对话"打开 → AI 自动问"这个模型和 Jev 的区别是啥"。

限制：移动端只能看 + 对话，不能编辑。

### PC vs 移动端入口对比

| 端 | 入口 |
|---|---|
| PC | 右键 / 双击 |
| 移动 | 微信"用其他应用打开" |

## 六、WorkBuddy 的产品哲学

### 路线分两条

| 路线 | 描述 |
|---|---|
| 对话框在前 | 你说一句，AI 在后台把文件处理完 |
| 文件在前 | 文件在前面，AI 在旁边，看着它一处处改进原文件 |

WorkBuddy 两条都在走。独立文件浏览器是后一条。

### 上下文 = 文件

> "Agent 的能力在文件夹，不在模型。"

文件就是最浓的那份上下文——打开它，背景、格式、改到哪一步，一次交给 AI，不用上传也不用再讲一遍。

### 腾讯整套牌

| 层 | 来源 |
|---|---|
| 编辑引擎 | 腾讯文档 |
| 存储后端 | 资料库 / 腾讯文档 / ima / 乐享 |
| 移动端 | 微信小程序 |

一个文件从打开 → 修改 → 入库 → 转发，都不出这条链路。

## 九、对 Sam 的 3 点启示

1. **入口之争的本质 = 文件上下文所有权**：腾讯 / 阿里 / 字节 / 微软争桌面 AI 入口，核心不是模型能力，而是"你的文件先经过谁"。Sam 部署 Hermes Agent 到校园 IT 时，应考虑"文件 / 邮件 / 课表"先到 Hermes 而非 GitHub Copilot / 腾讯 TIONE 的入口策略——可以通过对接校园 IT 系统（共享盘 / 邮件 / OA）建立"日常文件先到 Hermes"的心智
2. **"右键菜单 = 桌面 AI 入口" 是新共识**：腾讯 + 微软 + Anthropic + Google 都在走这条路线（WorkBuddy 右键 / Windows 右键 / Claude Desktop / Gemini Flow / Stitch）。Sam 设计 Hermes Agent 时也该考虑"右键集成"——Mac 平台 Finder 右键服务 / Windows 上下文菜单，让"选中文件 → 右键 → Hermes 处理"成为肌肉记忆
3. **"AI 面板默认收起"是好设计**：WorkBuddy 这个细节值得借鉴——Hermes Agent 不要强行 push 对话框，让用户先安静看文档，需要时主动唤醒。Sam 之前 OpenClaw `<compact_fallback>` 设计也是同源哲学："AI 在旁边，用户随时叫"
