一句话总结

OpenAI 发布 722 篇 AI 数学手稿不到 24 小时因”一个符号错误”撤回 3 篇（致 1 篇论证失效 + 2 篇构造失效），并修订另外 14 篇。康奈尔 Alex Townsend：“一个错误连锁导致 3 篇不意外，怀疑还会发现更多”。人类数学协会（AHM）10-07 声明”数学家没要求做这项工作……我们敦促数学家停止与 OpenAI 合作，回归以人类理解为中心”，陶哲轩全文转载。克莱数学研究所所长 Martin Bridson（牛津）：“对许多人兴奋，对其他人恐惧，对某些人毁灭性”；Northwestern Bryna Kra：“同行业评审没有了” + “公司正在破坏原本支撑这项研究的生态系统”；弗吉尼亚 Ken Ono（Axiom Math 创始人）：“被打在肚子上”；蒙大拿州立博士生 Thomas Carlson：“2028 年毕业生学位价值如何保证”。撤销/修订成为 OpenAI 数学发布模式的常态。

一、撤回事件经过

时间事件
10-06OpenAI 在 GitHub（github-openai-math 仓库）发布 722 篇 AI 生成数学预印本，372 个数学问题成果
10-07（不到 24 小时）OpenAI 宣布因”一个符号错误”撤回 3 篇手稿
10-07 同期OpenAI 修订另外 14 篇手稿（证明修补 / 陈述更正 / 更清晰假设与依赖关系 / 一处过时引用更正）

撤回范围

项影响
1 篇主论文论证失效
2 篇依赖论文构造失效（连锁错误）
14 篇修订（修补 / 更正 / 假设明确化）

康奈尔大学数学副教授 Alex Townsend：

“一个错误连锁导致 3 篇手稿出问题并不令人意外，我怀疑还会发现更多错误。”

二、OpenAI 官方回应

OpenAI 发言人：

“我们欢迎数学界的审查和反馈……在发现错误的地方，我们会努力及时纠正；如果找不到修复办法，就撤回论文。与其他研究手稿一样，这是一个迭代过程。”

迭代过程的实质：先发大量手稿，再让数学界免费审核，发现问题后批量修订或撤回。

三、AHM 声明：呼吁数学家停止合作

10-07 人类数学协会（Association for Human Mathematics, AHM）声明：

“数学家没有要求做这项工作。一次性发布 700 多份文件不是学术展示，而是权力展示。我们敦促数学家停止与 OpenAI 合作，回归以人类理解为中心的科学愿景。”

AHM 自我定位（官网自述）：

“致力于保护数学作为人类智慧的结晶，使其免受人工智能的威胁。”

菲尔兹奖得主陶哲轩全文转载 AHM 声明。

四、数学界具体反应

Martin Bridson（牛津大学数学教授 / 克莱数学研究所所长）

群论、拓扑学和代数领域的具体成果”问题清单中包含了一些曾是我自身研究中的关键挑战”。

“直到不久以前，还无法想象数学前沿能在一天内推进如此之远。”

“这些解决方案的公布会令许多人兴奋，令其他人恐惧，对某些人则是毁灭性的。”

Bryna Kra（Northwestern 数学教授）

“AI 写作的方式让人无法理解。”

“总体而言，这些结果是惊人的，但现在需要仔细检查数万页数学结果。通常，检查和验证由同行评审完成。在这个过程中，同行评审没有了。”

“所以问题是，这些人工智能生成的结果会产生什么样的影响？数学界将需要很长时间来消化。”

核心质疑：

“或许最相关的问题在于，以这种方式公开发布大量资料，公司正在破坏原本支撑这项研究的生态系统。”

Ken Ono（弗吉尼亚大学数学教授 / Axiom Math 创始人）

“我想许多数学家和我一样，感觉像被一拳打在肚子上。”

“对于努力推动数学前进的人来说，这是一个挑战，也是一次迈向更高目标的邀请。”

Thomas Carlson（蒙大拿州立大学博士生）

“我认为我们已经到了需要仔细考虑数学研究生学位的结构、要求和价值的时候。”

“我们能做些什么来确保 2028 年的毕业生所获得的学位，与 2023 年毕业生具有同等价值呢？”

这个担忧是争议里最贴近教育系统的——如果 AI 能 24 小时产出千页级证明 + 自由市场认可，那数学博士训练 4-5 年后证明的”原创性贡献”价值如何定价？

五、为什么”撤回”不是坏事（OpenAI 的角度）

OpenAI 的逻辑：

  1. 快速发布——覆盖广度（372 个数学问题，17 个方向）
  2. 公开验证——数学界免费审核
  3. 快速迭代——发现错误就批量修订或撤回

这是开源软件的迭代哲学搬到数学上：

软件模式OpenAI 数学模式
Push 大量 commits一次性 push 722 篇手稿
社区 review 找 bug数学界免费审核
快速修 commit快速修订/撤回手稿
不要求 100% 正确率不要求 100% 证明正确

OpenAI 发言人自己说的”迭代过程”就是这个逻辑。

六、问题：数学不是软件

但数学不是软件。关键区别：

维度软件数学
错误的成本重发版本修复即可引用错误论文的整套研究都受质疑
信任传递Git commit 公认可信论文需要”几何 / 代数 / 拓扑专家” 核验
修正速度几小时 commit 修复几周 / 几月 / 几代
评价标准功能能用即可证明是否”对”是 0/1

Kra 说的”同行业评审没有了”正是这个张力——OpenAI 跳过同行评审 + 事后让数学界免费审核 = 把”评审成本”从自己转嫁给学术界。

七、对 Sam 的 3 点启示

  1. “快迭代”哲学在数学领域有天花板——Bridson 指出群论 / 拓扑 / 代数等”曾是自身研究中的关键挑战”被 OpenAI 一波发布打穿，这意味 24 小时内的发布对数学家数十年的工作”价值认定”是一种挑战。Sam 部署 Hermes Agent 时应明示哪些 skill 输出需要数学/逻辑同行评审，哪些可以走”OpenAI 数学式快迭代”
  2. 撤回 / 修订不是”质量失败”而是”工业级迭代”——OpenAI 1 个月前承诺”质量优先”（Fable 5 与政府合作的 slow path），现在的 722 篇 release 已经转向”快迭代”路径。Sam 的 Hermes Agent 设计可以参考这个张力：对外承诺什么 vs 实际交付什么 之间的差距
  3. “学位价值”问题 —— Carlson 提的”2028 年毕业生学位价值”不只是数学问题，而是所有知识工作的问题。Sam 部署 Hermes Agent 到校园 IT 时，教师 + 学生的角色该如何重新定位？OpenAI 数学 release 给的教训是：如果工具太快，可能需要重新设计训练体系 + 评价标准，否则下一代毕业时手里的”原创”与”AI 几小时产出”边界模糊
