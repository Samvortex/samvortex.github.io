三、4 大创新（vs 传统网盘）

3.1 统一平面跨源（不是路径管理）

维度传统网盘Spacedrive
入口每个云盘 App 独立——iCloud / Google Drive / OneDrive 各打开一次一个平面——本地硬盘 / 网盘 / 远程服务器 / 移动盘 全部统一
搜索各 App 单独搜——不能跨云盘搜一个搜索跨所有源——本地 + 远程 + 云 + adapter 一起搜
迁移移动硬盘换电脑——目录结构全丢索引跟源走——搬家不丢结构
“内容寻址”文件用路径管理——移动就丢身份BLAKE3 内容寻址——身份跟内容走

3.2 BLAKE3 内容寻址（核心技术）

关键洞察：

「文件一旦被移动或改名，路径就断了，系统只能靠目录结构去猜它还是不是原来那个文件」——传统路径管理的问题。

Spacedrive 做法：

  • 用 BLAKE3 算法对文件内容做哈希
  • 依据内容分配全局唯一标识——「内容身份证」
  • 文件可跨设备自由迁移——身份跟着内容走，不跟路径
  • 查重按内容比对——不是按文件名或目录位置

实操价值：

  • 重复文件识别——BLAKE3 内容 hash 精确匹配——避免误删同名不同内容的文件
  • 数据迁移——身份跟内容——不依赖原路径
  • 加密保护——BLAKE3 也是加密哈希——文件完整性验证

3.3 离线快照

「Spacedrive 不需要任何云端中转服务器，也不追踪用户数据」

  • 本地快照让你断网也能翻完整套目录结构
  • 去中心化账号——没有托管方拿着你的元数据
  • 「把目录的知情权重新交回本地」

对比：

  • iCloud / OneDrive — 断网看部分缓存
  • Spacedrive — 断网看完整本地快照

3.4 数据主权（Data Sovereignty）

「对习惯了平台账号绑定的人来说，这等于把目录的知情权重新交回本地」

vs 传统网盘：

  • 平台账号 = 平台有你所有元数据
  • 离开平台 = 数据归属问题
  • 平台倒闭 = 数据风险

Spacedrive：

  • 账号 = 你自己的
  • 离开 = 数据跟着走
  • 「No hosted account, no vendor control plane, no telemetry」

5.3 对 Hermes Agent / The Hive 的启示

Agent 操作文件当前状态：

  • Hermes Agent 跑在云端——操作 EC2 / GCS 等**——**操作云盘 OK

Spacedrive 2.0 提供：

  • 统一 API——「one API for people and software」——Agent 可以直接调用——不需为每个存储介质写 adapter
